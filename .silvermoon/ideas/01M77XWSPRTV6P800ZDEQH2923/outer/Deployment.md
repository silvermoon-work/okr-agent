# 固定 TypeScript 与 npm 项目标准交付初版

## Steps

### D-S01: 准备独立 CAR 消费

在不依赖作者源码的环境消费两个准确新 CAR，仅使用公开 Task 工具、显式授权的检查对象与发行元数据来源；若组合扩展依赖新版 SDK，先明确可用的精确依赖，发布另行授权。

### D-S02: 验证对象输入与组合

以独立单包及 pnpm
workspace 项目验证六类标准、latest/rc 发布配置反例、单目录输入、旧输入拒绝、真实组合及元数据观测，核对父子问题、来源/时间、文档及回收；不实际执行目标发布 workflow。

### D-S03: 记录身份与迁移边界

记录新 CID、统一单目录输入、声明驱动范围、长期版本政策和旧输入的不兼容行为；区分规则身份与本次观测事实，不改写旧 CAR、历史验收或未经授权的外部引用。

## Acceptance criteria

### D-AC01: 独立消费可复现

实际结果证明没有作者源码或 workspace 隐含解析也能运行新 CAR。

### D-AC02: 标准与对象边界可观察

真实 Engine 证明单/多包项目按同一规则分责，脚本及 lockfile 反例可定位，发布路由不混淆包身份；旧输入与查询异常不判通过，父子文档可读且 Run 回收。

### D-AC03: 交付身份与范围真实

准确 CAR/CID 与迁移说明持久可用，不将本地验证声称为外部发布、pin 或未验证平台支持。
