# 统一 TypeScript 项目约定交付初版

## Steps

### D-S01: 准备独立 CAR 消费

在不依赖作者源码的环境消费准确新 CAR，仅使用公开 Task 工具、授权项目对象与发行元数据来源。

### D-S02: 验证统一项目约定

以单包、单/多成员 workspace、私有应用及 npm 交付项目验证六类约定和适用分支，包含旧输入拒绝、发行事实变化、查询失败及发布配置反例，不执行目标发布。

### D-S03: 记录身份与迁移边界

记录准确 CID、单目录输入、适用性、观测来源与时间，以及旧输入的不兼容行为；不改写历史 CAR 或未经授权的外部引用。

## Acceptance criteria

### D-AC01: 独立消费可复现

实际结果证明没有作者源码或 workspace 隐含解析也能运行统一 Check。

### D-AC02: 六类标准与适用性可观察

真实 Engine 证明规则覆盖适用代码及交付包，私有应用不误报发布要求；旧输入与查询异常不判通过，文档可读且 Run 回收。

### D-AC03: 交付身份与范围真实

CAR/CID、复现说明及限制持久可用，不将本地验收声称为 npm 发布、远程 pin 或未验证平台支持。
