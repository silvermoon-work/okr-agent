# 队列执行语义与可观察验收

本文件补充 [模型](./Model.md)，只定义调度保证和验证场景，不预写实现任务树。

## FIFO 工作队列，不设整层屏障

采用 FIFO 就绪队列、有界并发；这是广度优先倾向的工作队列，不承诺异步完成时
严格按图深度执行，也不要求同层所有节点结束后才运行下一层。
先入队者先取得空闲槽位；运行中节点独立完成，成功后的 children 按返回顺序
立即登记、去重、入队。根通过并不意味着整次检查通过。

```text
根项登记并入队
  → 有槽位时取队首启动
  → 正常完成：
      pass → 登记子项及关系，未访问项入队
      fail → 收集本节点的问题，不展开 children
  → 队列为空且在途工作为零 → 正常生成完整报告
```

节点身份在入队前登记，避免两个并发父节点重复排队同一子项。
共享节点不重复执行，仍保留所有不同父子边；同一父子关系重复出现不需要
重复的逻辑边。去重不是跳过未知结果并当成通过，需保留节点真实执行状态。

环与共享节点不同，但都不能导致重复调用或递归等待。第一版的边是展开关系，
不是“等待孩子完成才能决定父结果”；回边可以记录并通过访问去重终止展开。
不因为“另一个节点正在执行”就报环；若要限制环，需要显式协议/政策依据，
不能把并发中的共享节点误判为循环依赖。

不同父节点完成顺序可改变后续入队时机；在首次结果复用的工程假设下，
不承诺外部世界变化时不同调度仍产生同一观察。对于相同节点结果集合，
最终报告采用稳定节点顺序和节点内部问题顺序，不以完成先后形成随机输出。
具体稳定排序算法在实施时固定；它不能承担额外的业务问题合并。

问题按唯一节点收集，不能仅凭相同 code 跨节点去重。现有共享配置根因展示
如需归并，应作为显式领域归因保留影响范围，不能使独立失败丢失。

## 取消与执行故障

Checker 的 signal 是显式执行参数，不在 Target 中，不参与规范编码。
调度器自身订阅/检查取消：预取消不调用根；中途取消停止出队、新调用和子项展开，
把取消传给在途本地 I/O/Task，等待它们退出及清理后以取消结束。
取消后迟到的 pass 或 children 不能重启队列。

正常 `{ pass: false, problems }` 是业务发现，继续其他可达节点。
未知注册名、非法 target/result、适配协议不符、意外 I/O 或执行异常是故障：
停止新调度，取消并收束在途工作，保留真实错误，不生成正常完整 CheckReport。
停止后的清理失败也不能隐藏。运行中检查不能写入共享“当前问题数组”或
“当前成员 scope”造成并发串扰，必须按节点隔离并由执行器统一收集。

AbortSignal 是协作机制，不能强杀任意 JavaScript 函数。本地 Checker 必须
遵守取消并传递给底层操作；底层 Task 的超时/终止/回收沿用已有 Engine 保证，
不假装 Promise.race 或循环 break 已完成资源回收。
不响应 signal 的任意代码不能被宣称具有硬停止保证。

## 有界性

并发限制的是同时执行数，不是总节点数或队列内存。潜在图可以无限，
即使所有节点都不同也会消耗无限资源，因此需正整数并发上限、有限执行预算
和唯一节点/排队规模保护；预算耗尽以明确故障结束并清理，不返回通过。
精确默认值、编码大小限制和已有 Task 预算的组合方式在实施阶段确定，
用可测上限验证，禁止弱化门禁来绕过无限展开或清理失败。

## 验收场景

| ID | 场景 | 可观察的结果/证明 |
| --- | --- | --- |
| G01 | 同名 checker + 相等 target（属性插入顺序不同） | 规范键相等，只调用一次；不同 checker 或不等 target 不被误合并。 |
| G02 | 数字/字符串/数组/嵌套对象与非法表示 | 规范编码遵守已定义相等规则；非法值显式拒绝，往返一致；不静默遗漏值。 |
| G03 | 原 target 或返回的 child 在登记后被修改 | 实际执行值与登记身份一致；修改被隔离/拒绝，不污染访问表。 |
| G04 | 两个并发父节点返回同一子项，含已排队/运行/完成状态 | 子 Checker 总调用数为 1，两个来源边保留，子问题只收集一次。 |
| G05 | 自环、回边、菱形共享路径 | 有限节点不重复调用、不递归等待，不把正在运行的共享节点误当故障；图关系可核验。 |
| G06 | 根失败、子分支失败、独立兄弟与另一条有效路径 | 失败不展开新子项，其他可达检查继续，失败不全局封禁潜在目标。 |
| G07 | 慢兄弟与已完成父项的新子项，有可用并发槽位 | 实测在途数不超过上限，遵循已入队 FIFO，慢同层不形成整层屏障。 |
| G08 | 相同结果集合、不同完成顺序 | 最终报告顺序稳定；相同 code 的独立节点问题不被吞掉。 |
| G09 | 预取消、中途取消、取消后迟到 children | 调度调用轨迹证明取消后无新启动/展开，在途 signal 已传递，退出/清理可确认，不返回正常完整报告。 |
| G10 | 任一节点执行故障、多个在途工作、预算耗尽 | 停止调度并收束在途工作，执行/清理错误可见，无成功形状的兜底或未处理拒绝。 |
| G11 | 同一个根运行两次，第一次之后外部事实改变 | 每次执行独立观察；Run 内复用不泄漏成跨执行缓存。 |
| G12 | 任意合法根名、未知根、根 target 不匹配 | 不依赖 `$root`；类型测试和运行时验证覆盖 root/input/children 的对应关系。 |
| G13 | 本地 Checker 与由准确 CID 适配的 Check Bundle | 输入映射、通过/失败、非空问题、文档来源、取消/故障一致；非法协议拒绝，无未授权子调用。 |
| G14 | 两包迁移，含共享配置、坏成员、工具缺失及低版本 | 通用/非 Cloudflare 规则保留，根因与独立分支不串扰；无旧全局 mutable scope 的并发污染。 |

适配器测试明确消费的是单节点 CheckerResult 还是完整 CheckReport，不将两个
协议混用。若支持返回跨 Bundle 子项，增加注册名解析及不重复展开子图的契约测试；
若只适配完整报告为叶，明确该范围，不声称已支持跨 Bundle 的子节点协议。
