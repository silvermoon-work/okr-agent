# Implementation

## Steps

### I-S01: 确定描述契约

按构想阶段的明确决策定义文件位置、交付范围、路径与冲突语义；不重复平台原生配置。

### I-S02: 划分检查职责

补足通用类型与测试执行范围的设计，定义 Cloudflare 能力检查及与既有发布标准的迁移边界。实现范围须先解决 B03，不在准备阶段修改固定核心。

### I-S03: 验证标准一致性

在获准实施的范围内增加针对声明、冲突和职责边界的回归验证，并同步直接相关文档和标准资产。

## Acceptance criteria

### I-AC01: 描述语义唯一

契约或获准实现能唯一识别 npm/Cloudflare 交付项；通过正反例证明遗漏、重复和配置冲突不被默认为通过。

### I-AC02: 职责边界明确

以普通 TypeScript、静态前端、fullstack 和含 DO 的应用案例验证适用要求；设计阶段使用案例推演，实施后使用相应回归测试，不把静态机制当成行为执行证据。

### I-AC03: 迁移不削弱保护

核对现有映射与新契约的迁移方案；若获准修改实现，运行相关测试和根 check，证明质量及发布保护保留。
