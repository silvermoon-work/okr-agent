# Implementation

## Steps

### I-S01: 确定描述契约

实现根 `silvermoon.yaml` 的只读解析、开放类型及安全路径规则，按[设计决策](ideal/Decisions.md)区分缺失、不匹配与无法确认；不执行目标配置或重复平台配置。

### I-S02: 划分检查职责

实际调整 TypeScript Check、npm 专项及 publint/发布目标调度；将既有 npm 包 ID 迁入声明，核对 manifest 身份并移除旧独立目标清单，同步直接依赖的固定标准与仓库消费副本。第一阶段不扩建通用配置解释器或实现 Workers 专项；不以配置超出支持范围为由默许通过。准备阶段不修改这些实现。

### I-S03: 验证标准一致性

增加针对声明、迁移冲突和职责边界的受控回归，同步直接相关文档和标准资产；运行相关测试与根 `pnpm check`，如实记录工具版本和未通过项，不升级全局工具或降低门禁。

## Acceptance criteria

### I-AC01: 描述语义唯一

通过有/无交付项、单包 `.`、嵌套/重复/逃逸路径、非法/自定义类型、明确发布入口未登记和新旧来源冲突的正反例，证明清单是唯一交付意图来源，未知协议不冒充已支持。

### I-AC02: 职责边界明确

以普通 TypeScript、npm 应用/库和声明 Cloudflare 的代码项目进行回归测试，证明 strict、type-aware lint、格式、测试、四项覆盖率门禁保留，npm 专项不误套；明确超出现有静态配置能力及 Cloudflare 专项尚未验证。

### I-AC03: 迁移不削弱保护

逐项核对既有三个 npm 映射的 ID/name/path 不变，证明新版不回退旧清单且未登记目标不能被发布调度选中；通过受控测试及根 check 验证标准与消费副本一致，既有准确提交 CI、单包授权及全部发布保护不被声明绕过，不执行实际发布。
