# Implementation

## Steps

### I-S01: 确定描述契约

按构想阶段的明确决策定义文件位置、交付范围、路径与冲突语义；不重复平台原生配置。

### I-S02: 划分检查职责

实际调整 TypeScript Check 的交付识别、通用质量和 npm 专项适用范围，并迁移直接依赖的固定资产与发布映射。通用多配置支持按必要性细化；Cloudflare 专项留给第二阶段，不在准备阶段修改固定核心。

### I-S03: 验证标准一致性

增加针对声明、冲突和职责边界的回归验证，并同步直接相关文档和标准资产。

## Acceptance criteria

### I-AC01: 描述语义唯一

实现能读取 npm/Cloudflare 交付意图且不封闭自定义类型；通过正反例证明遗漏、重复和配置冲突按最终契约处理，不被默认为通过。

### I-AC02: 职责边界明确

以普通 TypeScript、npm 应用/库和声明 Cloudflare 的代码项目进行回归测试，证明通用检查保留、npm 专项不误套；明确 Cloudflare 配置和运行时专项尚未验证。

### I-AC03: 迁移不削弱保护

核对现有映射与新契约的迁移结果，运行相关测试和根 check，证明质量及发布保护保留。
