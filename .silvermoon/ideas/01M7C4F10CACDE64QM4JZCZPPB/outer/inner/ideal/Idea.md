# 按应用能力检查 Cloudflare 交付项

## 问题

通用 TypeScript 检查不能证明 Cloudflare 配置、前后端构建路由和 DO 等平台能力满足标准；直接复用旧检查也存在配置支持边界。

## 结果

在[第一阶段](../../../../01M7C33MXC53288148DJY4QW0X/outer/inner/ideal/Idea.md)完成交付描述和 TypeScript Check 调整后，为显式 Cloudflare 交付项增加按实际能力生效的平台检查。

## 边界

- 一个应用 Package 对应一个 Workers 部署目标，静态资产、服务端代码和多个 DO 类均为可选能力；不单列 realtime 类型。
- 复用第一阶段的交付意图和适用通用质量要求，不复制清单、不豁免质量门禁；独立包或组合方式留待设计。
- 保持只读静态检查，不执行目标模块、发布或远端迁移；IPFS 交付不在范围内。

## 验收标准

- 静态前端、API/SSR 和含 DO 的样例均有明确、按能力适用的配置检查。
- 平台配置、类型、测试及门禁职责一致；缺失、不匹配和无法确认明确区分。
- 交付准确 CAR/文档引用，静态通过不被表述为运行或线上部署成功。
