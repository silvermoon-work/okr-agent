# Implementation

## Steps

### I-S01: 确认通用底座接口

以第一阶段的实际交付为基线，确定复用与平台专项边界；必要的通用缺口单独明确，不以豁免绕过。

### I-S02: 实现平台能力检查

按首期确认范围检查配置、类型、资产路由和适用 DO/测试职责；不提前要求所有应用使用全部能力。

### I-S03: 验证并交付标准

增加针对支持形态与失败路径的回归测试，同步标准资产与修复文档并构建 CAR。

## Acceptance criteria

### I-AC01: 复用边界一致

通过普通 TypeScript 与 Cloudflare 交付项回归证明通用门禁保留，平台要求不误施加到无关项目。

### I-AC02: 能力检查准确

使用静态资产、服务端及 DO 案例的正反例验证已支持机制；未知形态明确无法确认，不假定通过。

### I-AC03: 制品和门禁可验证

通过构建、相关测试与根 check 验证 CAR、参考文档和标准资产一致，不宣称线上运行已验证。
