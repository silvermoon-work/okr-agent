# Implementation

## Steps

### I-S01: 确认通用底座接口

等待第一阶段的实际交付与验收，以根声明及 TypeScript Check 的真实支持边界确定复用方式，再确定本阶段首期范围；不预定独立包、调用协议或通用配置改造。必要的通用缺口单独明确，不以豁免绕过。

### I-S02: 实现平台能力检查

仅在首期范围明确后实现配置、类型、资产路由及适用 DO/测试职责的只读检查；一个应用 Package 对应一个 Workers 部署单元，资产/服务端/多个 DO 均可选，不强制 handler 或 realtime 类型，也不执行目标配置、模块、脚本或迁移。

### I-S03: 验证并交付标准

增加针对支持形态与失败路径的受控回归，同步标准资产与修复文档，按最终实现选择必要的本地产物；运行相关测试和根 check，不发布或上传。

## Acceptance criteria

### I-AC01: 复用边界一致

通过普通 TypeScript 与 Cloudflare 交付项回归证明通用门禁保留，平台要求不误施加到无关项目。

### I-AC02: 能力检查准确

使用静态资产、服务端及 DO 案例的正反例验证已支持机制；未知形态明确无法确认，不假定通过。

### I-AC03: 制品和门禁可验证

通过适用构建、相关测试与根 check 验证本地产物、参考文档和标准资产一致，保留 strict、type-aware lint、四项覆盖率及固定质量/发布保护，不宣称外部消费或线上运行已验证。
