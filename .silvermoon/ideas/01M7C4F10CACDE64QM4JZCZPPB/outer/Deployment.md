# Deployment

## Steps

### D-S01: 固定本地验证候选

将最终部署契约同步到 primary 并固定其准确修订，再固定接受后的同一 Check/CAR、样例、源码提交及摘要；若使用确定性元数据验证 CAR，须与生产 CAR 分别记录身份，不要求外部消费或发布。

### D-S02: 验证本地平台诊断

使用仓库内受控纯资产、API/SSR、多个本地 DO 及明确失败/无法确认样例，验证接受后的候选平台诊断、文档与制品身份，区分静态配置事实与运行行为。只运行检查器自身和获准本地验证，不执行被检查目标代码或 wrangler types/部署/迁移命令；不发 npm 包、不发版、不推送发布标签、不上传 IPFS/Pinboard、不部署或迁移 Cloudflare 资源。

## Acceptance criteria

### D-AC01: 本地候选可追溯

通过 primary 可达提交、部署契约准确修订及适用本地产物摘要证明验证候选与最终标准一致；不以 registry、远端 CID、外部消费者或 Cloudflare 账号资源作为门禁。

### D-AC02: 本地检查结果可读

记录受控样例的输入、通过/不通过结果和修复文档，证明首期平台诊断在本地可用；明确未验证外部消费、实际运行或 Cloudflare 部署，不以模拟结果替代它们。
