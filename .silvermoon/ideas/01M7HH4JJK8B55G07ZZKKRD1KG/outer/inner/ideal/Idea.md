# 按问题驱动重建 TypeScript 项目检查

## 问题

旧实现虽已注册为检查图，仍混合领域规则、共享可变状态和检查结论缓存，
难以逐层讨论每个问题的责任与阻断范围。

## 结果

从项目身份根节点开始，按 single repo / monorepo 分流，逐层增加明确拥有
问题的 checker；每轮交付可试跑的 CAR。已确认规则与候选方向见
[讨论续接](Discussion.md)，已有代码与验证基线见
[实施续接](../Handoff.md)。

## 边界

- 不恢复旧整套检查流程；旧实现仅作为参考及回归基线，不决定新设计。
- 检查只读，不运行目标代码；业务问题、执行故障及过程日志保持分离。
- 不在本次续接记录中宣告构想验收、发布或部署完成。

## 验收标准

1. 项目身份与分流符合已确认规则，问题归属和失败剪枝明确。
2. monorepo 的 workspace 全局职责与 package 职责分离，规则经逐层确认后实现。
3. 每轮保留可运行 CAR、准确试跑命令及对应验证，不把尚未检查的标准称为已验证。

## 下一步

先讨论 monorepo 的 workspace 声明和 package 成员发现：明确检查项、
具体问题、前置事实及阻断范围，再决定下一轮实现。
