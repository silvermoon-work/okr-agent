# Deployment

本契约是准备阶段的现实验证初版，不授权 npm 发布、远程上传/pin 或 Cloudflare 部署。

## Steps

### D-S01: 准备独立消费者与准确交付身份

在不链接作者源码的隔离消费者环境使用实施阶段确定的两个 CAR 与公开 Engine；
记录准确 SDK 候选包身份、CAR CID、平台与宿主授权范围。SDK 可通过本地
pack 验证消费；需要 registry 发布或外部平台资源时另行请求明确授权。

### D-S02: 验证两个 Check 的实际消费结果

用新 CAR 执行规划对应的通过、不通过与局部剪枝场景；从 output CID
读取业务结果和参考文档/资产，并验证故障、取消及资源回收边界。

### D-S03: 记录迁移说明与证据边界

提供准确新 CID、SDK 消费方式和旧制品不自动升级的说明；
区分受控消费验证、原生工具支持与线上平台验证，不复用历史成绩冒充本次结果。

## Acceptance criteria

### D-AC01: SDK 与两个 CAR 可独立消费

独立消费者可从候选 SDK 包导入新作者接口，两个 CAR 的已验证根 CID
与提交身份一致；通过公开 Engine 使用，不读取作者源码或 SDK 私有 API。

### D-AC02: 结果与文档协议实际保持

记录两个 Check 的成功/多问题失败与故障/取消结果、output 文档/资产读取
及回收证据；被前置阻断的分支没有派生报告，独立分支仍有对应发现。

### D-AC03: 迁移记录准确且无未授权发布

新交付身份、执行环境与验证范围可复核，旧 CAR/CID 不被覆盖。
无明确授权不发布 npm、上传/pin 或部署 Cloudflare；没有线上证据就不声称线上成功。
