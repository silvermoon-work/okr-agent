# TypeScript 项目配置 Check 实施计划

## Steps

### I-S01: 确认默认政策与输入契约

根据用户代理授权确定默认值、输入、错误和领域依赖，保持项目配置与宿主工具链、实际运行成绩的边界。

### I-S02: 实现纯归一化与类型契约

复用仓库现有契约机制，提供完整内部 requirements 和确定性 normalize，并实现只读有界的静态配置检测及问题文档，不运行目标代码。

### I-S03: 验证边界并提供使用说明

为归一化和各领域配置正反例、无法确认、越界与动态配置添加测试；构建真实 CAR 并验证 Engine 结果与文档。

## Acceptance criteria

### I-AC01: 要求完整且无歧义

以测试证明缺省与局部输入按已确认政策生成完整内部要求，检测器无需再次补默认；关闭状态不保留有效规则。

### I-AC02: 错误与副作用边界可靠

以测试证明错误类型、未知字段、非法阈值与跨域冲突返回定位明确的错误，且输入不被修改，不读取项目或探测设备。

### I-AC03: 首期交付范围真实

实际配置测试与 CAR/Engine 证据一致，相关检查及 `pnpm check`
验证；已有无关失败单独披露，不能声称未验证能力。
