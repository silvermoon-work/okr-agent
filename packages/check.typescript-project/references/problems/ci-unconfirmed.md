# 无法确认 CI 配置

YAML、事件过滤、动态引用或其他结构超出静态支持范围。检查不访问 GitHub、不运行工作流，也不把未知配置猜测为通过。

先比较固定质量 workflow 结构，再解释标准 compatibility 矩阵；其他 job
ID 上存在矩阵时报告 ci-mismatch 的实际路径/值和标准结构差异，不将未声明标准路径误报为缺少矩阵能力。结构未通过不追加派生矩阵或发布绑定问题。

结构与所有适用代码包统一最低值前置通过后，消费者最低版本检查独立于发布映射与 release.config.json；缺失/非法或最低值不一致先报告环境问题，短路依赖的矩阵差异，独立默认 CI/发布保护仍检。required 是统一最低值和更高受支持官方 LTS，unsupported 额外条目不等于消费者承诺，但现有完整开发 check 仍会执行全部矩阵。兼容性属于质量门禁，不另立发布前整套检查；消费者最低 Node 不必支持全部现代开发工具，固定 profile 无法独立证明运行兼容时准确报告边界，不要求缩窄 engines，也不擅自添加新消费者 probe。这不等于本次线上 CI 已执行成功。
