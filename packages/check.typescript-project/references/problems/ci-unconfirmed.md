# 无法确认 CI 配置

只对某个适用显式谓词无法证明时报告此问题，例如事件过滤无法证明相关路径覆盖、
动态矩阵无法枚举必需身份、并发表达式无法证明 PR/main 隔离、有关 env/defaults
无法证明必需命令语义。brief 给出准确路径、观察值和未证明的谓词。无关未知字段、
通知 job 或无害扩展本身不是 unconfirmed；检查不访问 GitHub、不运行工作流。

先验证
[质量与发布共享谓词](../npm-publisher-v1.md#ci-与事实边界)，再解释 compatibility
矩阵。稳定质量/矩阵/聚合身份由远端发布器绑定，不是模板白名单；
无关 job 的名字和矩阵可扩展。必需谓词未通过不追加派生矩阵或发布绑定问题。

结构与所有适用代码包统一最低值前置通过后，消费者最低版本检查独立于发布映射与 release.config.json；缺失/非法或最低值不一致先报告环境问题，短路依赖的矩阵差异，独立默认 CI/发布保护仍检。required 是统一最低值和更高受支持官方 LTS，unsupported 额外条目不等于消费者承诺，但现有完整开发 check 仍会执行全部矩阵。兼容性属于质量门禁，不另立发布前整套检查；消费者最低 Node 不必支持全部现代开发工具，固定 profile 无法独立证明运行兼容时准确报告边界，不要求缩窄 engines，也不擅自添加新消费者 probe。这不等于本次线上 CI 已执行成功。
